# Black sky: the second intentional chart palette

Generated by `make black-sky-study` (juranometria.tool.BlackSkyStudyMain), which renders the representative pages beside this document through the production renderer in both palettes, executes the derivation rule against the white-paper palette, and fails the run if `ChartPalette.BLACK_SKY` is not what the rule derives or any pixel breaches its contract. Pixel counts are per machine, like the furniture study's.

## The rule: equal contrast, not inversion

Every ink keeps the WCAG contrast ratio against its ground that it earned on white paper: for a paper ink of relative luminance *l*, the black-sky partner is the grey nearest luminance `0.0525 / (l + 0.05) - 0.05`. Because sRGB luminance is non-linear, this is visibly not a channel mirror - the mid-greys land dimmer than `255 - v` would put them, which is exactly the restrained light ink the issue asks for, falling out of the rule rather than being tuned by hand. The mapping is monotone, so which ink is more prominent than which is preserved without a separate rule.

## The pages, and every pixel accounted

Each page is rendered in both palettes (900x700; committed beside this document as `<page>-paper.png` and `<page>-black.png`). For the black render, three contracts, asserted: every pixel is grey; every colour covering at least 0.5% of the page is a reviewed palette value (an accidental white island or a furniture block on the wrong ground is thousands of pixels; the antialiased rim of a long feature is a legitimate concentration of a single intermediate grey - the first run caught 531 pixels of grey 1 along M31's ellipse rim, honest compositing a naive floor misread); and every remaining colour is counted as antialiasing, not waved through. Then the two renders are compared structurally, pixel for pixel, each classified ground / exact ink / antialiased: compositing against the wrong ground would put antialiasing where the paper render has none, so the classification agreement is the halo check made executable. "Mask" is the set of non-ground pixels; its residual disagreement is rounding at edges where coverage is marginal against one ground but not the other.

## What stays constant, and where it is proven

- **The white-paper chart is byte-identical.** `ChartOptions.DEFAULTS` carries white paper, every released reference comparison and ink-count test runs through it unchanged, and the palette reaches rendering only through the options value.
- **The application theme never reaches chart ink.** The palette lives in `ChartPalette`, consulted only by the chart's own painters; the renderer reads nothing from `UIManager`, and the both-themes byte-identity tests now run the black page too.
- **Enlarged application text does not reach the page.** Chart label faces are the renderer's own fixed fonts, not the application's `defaultFont`; the dialog and its Black sky control follow application text size like every other control.
- **Switching is repaint-only.** The palette is a `ChartOptions` component, invisible to scene assembly by construction; the scene, inventory, catalogue-query count, centre, field, limit, target, selection, and working marks are untouched, asserted by the journey tests.
- **Modules stay colour-free.** They contribute typed geometry and ink roles; the chart's two ink painters translate role to palette colour.

## The Milky Way, deferred

`ChartPalette` deliberately carries no Milky Way colour: that imagery is parked unlicensed (Sprint 22), and choosing its dark-ground treatment before the source is licensed would be a palette chosen in advance of its data. The compatibility question is recorded in docs/decisions/black-sky.md, not answered here.
